## 待办事项

1. OSG 多父原生支持（高优先）
   - 当前 OSG 仍按单父关系运行，使用首父映射。
   - 建议后续将 `m_backendParentIds` 升级为多父结构，并统一 `isBackendDescendantOf` 逻辑。

2. 删除策略细分（高优先）
   - 当前删除为“删除节点及可达后代”。
   - 建议新增两种可选策略：
     - `detach_only`
     - `delete_orphans_only`（仅删除失去所有父的后代）

3. 自动化测试基建（中优先）
   - 当前工程未发现现成单测框架入口。
   - 建议补一个 `BackendDataManager` 单测目标，覆盖：
     - 环检测
     - 多父查询
     - 序列化回读关系一致性

4. 关系编辑 API 对外暴露（中优先）
   - 目前关系主要在导入/加载流程中使用。
   - 建议补 UI 侧关系编辑命令（挂接/断开）与撤销重做。

5. legacy 镜像收敛（低优先）
   - `backendParentId` 当前为兼容镜像。
   - 等上层全部切换后可逐步下线，减少双源维护成本。

## 建议执行方式

- 第一步先做测试基建（保障后续改动稳定）。
- 第二步实现 OSG 多父数据结构。
- 第三步补删除策略与 UI 交互。
- 第四步清理 legacy 映射与旧字段写入。
