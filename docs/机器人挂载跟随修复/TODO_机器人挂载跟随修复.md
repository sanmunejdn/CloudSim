## 后续优化方向（方案三：统一运动时钟 / 场景运动调度器）

**背景**：当前机器人播放（`RobotSimulationController` 定时器）、设备姿态运动（`DevicePoseMotionPlayer` 独立 16ms 定时器）、传送带等运动各自为政，分属不同时钟域。方案一已修复状态真源分裂（空间一致性），但**时间一致性**仍靠「各自 tick + notify 时序恰好正确」维持：

- 设备姿态运动与机器人运动在同一帧内的 apply 顺序由定时器触发先后决定，非显式编排；
- 虚拟时钟/时间缩放/逐帧步进难以统一实现；
- 未来更多运动体（外部轴联动、多设备协同）会放大编排复杂度。

**方向**：引入场景级运动调度器——统一时钟域（虚拟时钟驱动所有运动体），每帧按显式优先级编排 apply 顺序（如：传送带 → 机器人 → 设备 → follow 解算 → flush），运动体注册/注销由调度器管理。

**价值**：时间一致性收归框架；支持时间缩放、暂停/单步、确定性回放；为数字孪生级仿真打底。

**代价**：需重构现有定时器驱动点（RobotSimulationController / DevicePoseMotionPlayer / HeadlessRobotPlaybackBridge），工作量大，建议在方案一稳定运行后单独立项。

**与方案一的关系**：方案一是方案三的前置——真源统一后，调度器只需编排「何时 apply」，不必关心「状态往哪写」。
